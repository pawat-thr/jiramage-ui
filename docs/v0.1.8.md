# v0.1.8 (beta) — What's new since v0.1.7

> beta.1 in progress. Pre-release builds show the git hash again (`v0.1.8-beta.1+<hash>`).

## 🐞 Spec-link cache bug (teammate couldn't map specs after pulling)

- Root cause: the spec-link localStorage cache (`jiramage-spec-links-*`) persisted
  results **even when the fetch had failed**, and survived version upgrades — so a
  bad/empty cache from an old build suppressed Spec chips for up to 24h after pulling a fix
- Fixed: the cache key is now **version-stamped** (any new build starts clean and
  deletes old-version caches), and **failed fetches are never persisted** (they retry next session)
- Teammates on old builds: pulling this version self-heals — no manual localStorage clearing needed

## 🔥 Burn tracking on Team Task

- Cards in **In Dev / In Dev Testing** (configurable: `BURN_STATUSES` env) show a **burn meter**
  under the status (Jira time-tracking style): a mini progress bar + `12.4 / 16 pt` — burned points since first entering dev vs the estimate (1 manday = 8 points); **blue** on track, **amber** at ≥75%, **red** when over
- Manday math: Mon–Fri only, **09:30–12:00 + 13:00–18:30** (= 8 working hours, lunch excluded); weekends excluded. Hardcoded for this beta — a Settings work-time option is planned
- Dev-start comes from the issue **changelog** (first transition into a burn status), cached in
  localStorage (immutable per issue+status); chip turns **red when burn exceeds the estimate**
- Cards not in those statuses show nothing (as specified); 9 new unit tests for the working-time math (134 total)
- New env: `BURN_STATUSES=In Dev,In Dev Testing`

## 📊 Burn UX round 2

- Burn moved from under the status pill into its **own "Burn" column** on Team Task (My Tasks unchanged) — meters align down the column; non-dev rows show a dash
- Meter is a Jira-time-tracking-style widget: `12.0 / 16 pt` + staged progress bar (**blue** on track, **amber** ≥75%, **red** over) — no emoji
- **Unestimated subtasks are now visible**: subtask rows without story points show an amber **"no estimate"** badge in the Burn column; in-dev cards without points show `X pt · no estimate` in amber
- **Dashboard "Active subtasks · points"**: each member with in-dev cards gets a second thin bar — **dev burn vs estimated points** (sum of burned points ÷ sum of estimates on their in-dev cards, 1 manday = 8 pt), same blue/amber/red staging, with a `burn X / Y` label
