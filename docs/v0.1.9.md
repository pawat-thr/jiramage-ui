# v0.1.9 (beta) — What's new since v0.1.8

> **beta.1 in progress** — the LAST demo version before 0.2.0.
> Pre-release builds show the git hash (`v0.1.9-beta.1+<hash>`).

## 🏢 KEY FEATURE: Org system + Atlassian SSO (in progress)

The headline of 0.1.9 — full design in **docs/PLAN-ORG-SSO.md**:
Atlassian SSO (per-user Jira identity, env token gone), teams by subdomain
(`mp.localhost` / `aoa.localhost` in this version; real DNS in 0.2.0),
members/invites replacing TEAM_EMAILS/QA_EMAILS, admin team creation.
Built and demoed locally in 0.1.9; 0.2.0 only adds real hosting.

**Phase 0 implemented** (SSO, code complete):

- `server/ssoPlugin.js` — vite middleware (same logic moves to the 0.2 server):
  `/auth/login` → Atlassian consent (CSRF state), `/auth/callback` → code
  exchange, **whitelist check = the email must already exist as a Firebase
  Auth user** (nobody auto-created; delete the user in Firebase Console to
  revoke), Firebase custom token minted (firebase-admin + service account),
  httpOnly session; `/jira/*` proxied with the USER's Bearer token via
  api.atlassian.com (refresh-on-401 with Atlassian's rotating refresh
  tokens; Confluence via /wiki mapping with env-token fallback for spec
  chips); sessions in-memory, tokens never reach the browser
- client: silent `signInWithCustomToken` on load (ssoClient + useAuth);
  **LoginPage becomes a single "Continue with Atlassian" button in SSO mode —
  no passwords anywhere**; Settings hides Change-password under SSO; logout
  clears both the Firebase and server sessions
- no SSO creds in .env → everything behaves exactly as before (legacy
  password login + env-token proxy; e2e green)
- **SSO hardening round** — adversarial review confirmed 8 defects in the
  fresh SSO code, all fixed: (1) a race let the env allowlist sign out SSO
  users whose Firebase session restored before the status probe; (2) parallel
  401s raced Atlassian's single-use rotating refresh token and could destroy
  a valid session → one shared in-flight refresh per session; (3) **a stale
  SSO cookie silently fell through to the env token — the user's writes would
  be attributed to JIRA_EMAIL**; now 401 + cookie-clear, env fallback only
  for cookieless (individual/e2e) requests; (4) /auth/session served the
  callback-time custom token forever (dead after 1h) → minted fresh per call;
  (5) a transient /auth/status failure was cached as "SSO off" for the page's
  lifetime → failed probes retry; (6) Confluence fallback widened to 404
  (ex/confluence path-shape ambiguity); (7) the proxy now forwards
  Range/conditional headers, replays media/download headers, and STREAMS
  bodies (video seeking, download filenames, no double-buffering); (8) CSRF
  states get a 10-min TTL + sweep instead of accumulating forever
- **Jira access matrix** (verified live in all three cases): no Firebase →
  `JIRA_TOKEN` required (minimum app); Firebase + SSO → **tokenless** — every
  signed-in request uses the user's own Bearer token and the legacy proxy
  sends no auth at all; neither configured → a clear blocking screen
  ("No way to reach Jira") instead of silent 401s everywhere
- setup: OAuth app (developer.atlassian.com) + `ATLASSIAN_CLIENT_ID/SECRET` +
  Firebase service-account JSON (`serviceAccount.json`, gitignored) — see
  docs/PLAN-ORG-SSO.md
- **VERIFIED LIVE end-to-end**: real Atlassian consent → whitelist lookup →
  custom-token sign-in, no password anywhere. Debug journey captured for
  posterity: errors now surface on /login (the redirect used to drop them);
  firebase-admin was REMOVED entirely after two interop failures (namespace
  API dead under ESM import; v14 needs Node ≥22.12 for ESM jose; v12's error
  tables broke in the bundled config) — replaced by ~60 lines of plain
  Google REST + Node-crypto RS256 JWTs (user lookup + custom-token mint),
  each call proven against the real project before shipping

## Planned for this version

### ⏰ Work-time + work-days settings (burn & capacity schedule is configurable now)

New **`WORK_TIME`** config: comma-separated `HH:MM-HH:MM` windows, Mon–Fri
(lunch break = simply not a window). Default `09:30-12:00,13:00-18:30` — the
exact behavior that was hardcoded through 0.1.8.

- part of the movable team config: **Firebase > .env > default** per the usual
  precedence, editable in Settings → Team configuration with validation
  (windows must parse and end after they start); in .env for individual mode
- burn math derives hours/day from the windows (1 manday = one full set of
  windows; 1 manday still renders as 8 points — the team's point scale);
  parsed lazily + cached so the Firebase overlay applies without code changes
- invalid values fall back to the default instead of breaking burn
- burn-meter tooltips show the configured windows
- **`WORK_DAYS`** too (default `Mon,Tue,Wed,Thu,Fri`): day names, 3-letter or
  full, any case — days NOT listed are days off (0 planner capacity, no burn).
  Drives BOTH burn math and the Capacity Planner (day-off dimming + default
  capacity; `isWeekend` became `isDayOff`); same precedence/validation/fallback
  as WORK_TIME
- **inline validation, live while typing**: a malformed WORK_TIME / WORK_DAYS
  (or any validated field) shows its error under the input immediately — no
  submit needed — turns the field red, and disables Save until fixed; inputs
  gained aria-labels (a11y + testability)
- tests: window + day parsers, hours/day derivation, custom-window manday
  math, Saturday-as-workday burn + auto-place, Settings validation, and a
  TeamConfig component test locking the type→error→Save-disabled flow
  (193 unit tests total)

### 💬 Comment + ✏️ points editing on Jira cards

The detail view (page + overlay — so every page that opens a card) can now
WRITE to Jira, acting as the API-token user (`JIRA_EMAIL`) like all writes:

- **Comment on any issue type**: composer under the Comments list — multi-line
  (newlines become ADF paragraphs), Ctrl/⌘+Enter to post, explicit "posts as
  <token user>" attribution hint, inline error on failure, silent refetch so
  the new comment appears without a loading flash
- **Points editing on subtasks**: the Points meta gets an inline edit → number
  input (Enter saves, Esc cancels) — works on unpointed subtasks too, so the
  amber "no estimate" cards can be fixed right from the app
- **@mentions in comments**: same autocomplete as PR comments (type `@`,
  arrows/Enter to pick) with candidates = dev roster + QA team; known names
  post as REAL ADF mention nodes (accountId resolved per member, cached), so
  Jira itself notifies the mentioned person; unknown @names stay plain text
- **pictures in comments**: 🖼 Add picture button or PASTE a screenshot —
  files upload as issue attachments (multipart, XSRF-exempt header) and embed
  in the comment as external-media blocks (alt = filename, which our own
  renderer matches back to the attachment and streams through the proxy);
  if Jira rejects the embed the comment auto-reposts with "📎 filename"
  references instead, so posting never fails because of the picture
- new API: `addComment` (+ `textToAdf`/`commentAdf`), `setPoints`,
  `uploadAttachments`; payload shapes verified against intercepted requests;
  tests for the ADF builders incl. mention tokenization and media blocks
  (198 unit tests total)

### 👤 Profile pictures

- **Settings → Profile**: upload a picture (cropped square, resized to 128px
  client-side) or remove it to go back to the classic initials avatar
  ("PA in yellow") — which stays the default for anyone without a photo
- team mode: stored as a small data-URL in Firestore `profiles/{email}`
  (~10KB — no Firebase Storage needed), live via onSnapshot so the whole team
  sees each other's photos everywhere; **rules: everyone reads, each member
  can only write their OWN doc** → ⚠ republish firestore.rules
- individual mode: your photo saves to this browser (localStorage)
- one shared **`<Avatar>` component** now renders every person-avatar in the
  app (dashboard LOAD/BURN rows, planner, pickers, mentions dropdown, PR
  reviewers/comments, team board, inbox, story/subtask details, Settings) —
  photo when available, initials otherwise; label color-dots untouched

### 🧹 Cleanup + ⚡ performance round (pre-release)

- **Code splitting**: every page is now its own lazy chunk (first paint ships
  shell + dashboard only) and React/Firebase live in stable vendor chunks —
  the main bundle dropped **1,096 KB → 107 KB** (292 → 33 KB gzip); a page's
  code downloads on first visit and is then cached
- **Planner hover is render-free**: hover-tracing a task (ring all its chunks
  + dock chip) used React state and re-rendered the whole table per
  mouse-move; now it toggles a CSS class imperatively via data attributes —
  zero re-renders, verified with a real mouse drive
- adversarial review of the v0.1.9 work: 5 findings fixed (remove-photo
  success toast on failure, PointsEditor double-submit via Enter, burn
  tooltip hardcoding Mon–Fri instead of the effective WORK_DAYS/WORK_TIME
  schedule via new `workScheduleLabel()`, the mention regex triplicated →
  single `MENTION_RE` export, duplicate import statements)
- 21 unused imports purged (Avatar-consolidation leftovers); zero unused
  exports/files/deps; no debug leftovers

### 👥 Teamage — team membership (draft of Phase B)

New page **Teamage** (`/teamage`) + env team mapping:

```
TEAMS=mp,aoa
TEAM_LEADS=lead.mp@company.com,lead.aoa@company.com   # parallel: TEAMS[i] ↔ TEAM_LEADS[i]
```

- **Leads** (from env) see the Teamage page in the nav and manage THEIR
  team's members: add by email, remove with confirm, live member list with
  avatars + "added by"; members stored in Firestore
  `teams/{slug}/members/{email}` (new rules block → **republish required**)
- **Login is unchanged**: Firebase Auth stays the whitelist (add users in
  the Console as today). Teamage decides WHICH TEAM a signed-in user sees
- **No team → landing page**: a signed-in user not in any team gets a
  "No team yet — ask your lead to add you on Teamage" screen (with logout)
  instead of the app
- **Team data scoping for free**: once membership resolves, the team's
  member list is overlaid onto the roster (CFG.teamEmails) — dashboards,
  Team Task, the planner, pickers and mentions all show THAT team, zero
  call-site changes (same overlay trick as team config). Side-fix: "(me)"
  on dashboards now follows the logged-in user, not env JIRA_EMAIL
- **Empty TEAMS or no Firebase → feature off**, env roster exactly as before
  (e2e green on the off-path)
- **JIRA_EMAIL de-individualized** (deploy prep): the login user now
  OVERWRITES CFG.email on sign-in — "(me)" badges, isMe stats and the
  comment-attribution hint follow whoever logged in, and the attribution
  wording says "your Atlassian login" under SSO. JIRA_EMAIL/JIRA_TOKEN are
  documented as a Basic-auth PAIR: individual mode needs both, an SSO
  deployment sets NEITHER (verified: tokenless+emailless env boots clean)
- **tenancy decision changed**: single URL for all teams (subdomains
  dropped — no DNS/TLS gymnastics); your team shows in the sidebar brand
  block as "for team {X}" (main + QA mode)
- lead-only editing is client-enforced for this draft (rules can't read env);
  hardens in Phase C when teams/leads move fully into Firestore
- test maintenance: SubtaskGen suite now pins `specSpace` via module mock —
  it no longer depends on the developer's real .env

### 👥 Teamage round 2: pick from the whitelist + one team per person

- **"People without a team" picker**: Teamage lists every whitelist user
  (Firebase Auth) who's in NO team yet — click a chip to add them to your
  team in one tap. Powered by a new session-gated `/auth/users` server
  endpoint (service-account listing; 401 without an SSO session); the
  section hides gracefully when unavailable. Refreshes as members change
- **One team per person, validated**: adding someone who's already a lead or
  member of ANOTHER team is blocked with a clear message ("X is already a
  member of team AOA — one team per person"); the picker respects this by
  construction (it only shows team-less people)
- tests: env lead-mapping, the whitelist diff, teamsEnabled (204 total)

### 🗑 QA Mode retired (superseded by Teamage)

A QA team is just a TEAM now — add it in env (`TEAMS=mp,qa` + its lead),
the lead manages members in Teamage, and the whole app shows that team.
Removed: the `/jiramage/qa` sub-site (QaApp shell, routing, the TopBar
"QA Mode" switch), the blue `data-mode='qa'` theme, `fetchQaIssues`, and the
3 QA config fields (`QA_EMAILS`, `QA_BURN_STATUSES`,
`QA_BURN_FINISHED_STATUSES`) from env + team config (now 12 fields; stale QA
fields in the Firestore config doc are ignored harmlessly). The Capacity
Planner moved to a neutral home: `src/pages/CapacityPage.jsx` + the engine
at `src/features/capacity/capacity.js`; the `qaPlan` Firestore collection
stays (it's the planner's persistence, keyed per email + month). A QA team's
burn statuses are per-team team config once Phase A scopes config per team —
until then the shared BURN_STATUSES applies.
