# beta.1 — complete ✅

## 🔀 PR Review

- **Two sections on the board:**
  - **"Waiting for your review"** on top — PRs where YOU are a reviewer and the status is not yet Approved or Merged, with a count badge. Independent of the filters, so nothing you owe the team can hide.
  - **"All PRs"** below — the full filtered list, unchanged.
  - The top section disappears entirely when you're caught up.

## 📄 Subtask → Confluence spec links (My Tasks & Team Task)

- Subtask rows show a **"Spec ↗" chip** linking straight to the matching Confluence spec page — e.g. subtask `[BE][MP] mp-merchant/pre-order/orders/get-order-detail` links to page `[R6.1#5][S12] POST /campaigns/v1/mp-merchant/pre-order/orders/get-order-detail`
- Candidate pages come from the parent story's **remote links** ("mentioned on" Confluence pages) plus smart links in its **description** — no Confluence API needed
- Matching is token-sequence based with a confidence threshold; **camelCase splits** so GRPC-style names work (`GRPC ValidatePreOrderCart` ↛ `ReservePreOrder`); short generic names ("[QA] Test case") deliberately never match
- Both Confluence URL forms supported (`viewpage.action?pageId=` and `/pages/<id>/slug`); hovering shows the page title
- Links are fetched lazily per parent story, cached in memory **and in localStorage for 24h** (max 400 parents) — reloads don't refetch

## ⚡ Dev prompt templates

- **Settings → Dev Prompt**: a prompt template with a required **`{link}` param — exactly once** (live validation + a `+ {link}` quick-insert button that disables once present). Default: `help me to enhance {link} use skill unit test after implement`
- **Global**: stored in Firestore `settings/global` — one template shared by the whole team, live-synced. Individual mode falls back to this browser's localStorage (updates live there too)
- **⚡ Prompt button** on My Tasks / Team Task rows that have a Spec link → wide responsive popup with the generated prompt (`{link}` → that card's spec URL), spec-link header, **Copy** / **Close**

## 💬 @Mentions in PR comments

- Type **@** in the comment box → autocomplete dropdown of team members (filter as you type; ↑/↓ + Enter/Tab to pick, Esc to dismiss); works on mobile (no clipping, scrolls at 20+ members)
- Mentions render **highlighted** in posted comments
- Every mentioned member gets a **"mentioned you in a comment on"** inbox notification; the PR owner still gets the plain "commented" one — never both (mention wins), never self-notify

## 🗑 Story List removed

- The **Story List page is gone** — Delivery Tracking covers it (same stories, release/status filters, search, story detail at `/delivery/<KEY>`)
- The "Set as default" release button was removed with it — Delivery still auto-opens on your previously saved default release
- `/story-list` (and any unknown URL) now **redirects to home**; deleted `StoryListPage.jsx` + `StoryTable.jsx` (`releaseNames` extracted to `features/story/releaseNames.js`)

## 🔔 Notifications & sound

- **Ping is ~7× louder** — full-scale gain through a shared compressor (no clipping), triangle wave for presence; softer 5-minute reminder scaled up too
- **Retention**: once per session, READ notifications older than 30 days are silently deleted — the inbox collection no longer grows forever

## 🎨 UX / responsive fixes

- Task tables (My Tasks / Team Task / former Story List pattern) **scroll sideways on phones** instead of clipping columns; move/assign buttons always visible on touch screens
- Mention dropdown no longer clipped by the comments card when a PR has few comments
- Dev Prompt popup redesigned: wide, grows to 50vh with internal scroll, spec-link header, mobile-friendly two-column buttons
- Keyboard nav shortcuts (1–8, h) are suppressed while **any** popup is open
- Settings "+ {link}" button inserts at the caret (keeps textarea focus)
- Delivery `MAX_STORIES` consistency: the table shows exactly the story set the rollup covers

## 🧪 Full-version test suite

- **101 unit tests** (was 64) — deliveryUtils, exportXlsx (SheetJS mocked), MemberPicker, PromptModal, MentionText/MentionTextarea, NotificationBell (incl. no-re-ping-on-reconnect), InboxPage, LoginPage checklist, notification pruning

Exits non-zero on failure — CI-ready. `CHROME_PATH` overrides the browser binary.

# beta.2 — complete ✅ (finalized as 0.1.7)

## 🔗 Integration Plan (team mode)

- New page: pick a Release → **⟳ Sync from Jira** pulls its stories into a Firestore-backed plan (`integration` collection). Sync rules: new in Jira → added; already stored → **your inputs are kept** (name/status refreshed); gone from Jira → removed. No realtime listener by design — data loads on open / after sync
- Excel-style table with **frozen Key / Name / Status** columns + editable **Env** (text), **one Target-Date column per role** (`INTEGRATION_ROLES` env, default BE, WEB, MOB), and **Remark** — edits stay LOCAL until you push the sticky **💾 Save N changes** button (one Firestore batch); Sync is disabled while unsaved changes exist, and closing the tab warns you
- Per-row **✕ remove** (hover, always visible on touch) with a confirm dialog — note a removed story returns on the next sync if it's still in the release
- Click Key/Name → full story detail at `/integration/DX-123` (same as Delivery)
- New env: `INTEGRATION_ROLES=BE,WEB,MOB`


## ✨ Spec Wizard (beta) — the key feature

- New page (both modes): **search a story → its "mentioned on" Confluence specs become a suggested subtask checklist → rename/remove/add rows → one click bulk-creates them on the story**
- Suggestions are page titles with bracket prefixes stripped + the configurable prefix (e.g. `[R6.1#5][S12] GRPC Foo` → `[BE][MP] GRPC Foo`)
- **Duplicate-safe**: existing subtasks claim their best-matching spec page (reuses the spec-matcher in reverse) — covered specs show under "✓ Already covered", never re-suggested
- **Space filter**: pages outside `CONFLUENCE_SPEC_SPACE` are skipped with a note (space key looked up via the Confluence API through the same proxy/token)
- Each row can set an **assignee** (from `TEAM_EMAILS`, resolved to Jira accountIds) and **story points** — both verified available on the project's subtask create screen
- **Role sections** (dynamic roles):
  - **BE** — spec-driven suggestions (as before)
  - **FE** — manual: "+ Add FE" rows with the FE prefix prefilled
  - **QA** — the standard 9-pattern checklist from QA Info (`QA_CATEGORIES`), pre-populated; categories an existing subtask already covers go to "Already covered" instead
  - Env: `SUBTASK_PREFIX` split into `SUBTASK_PREFIX_BE` / `SUBTASK_PREFIX_FE` / `SUBTASK_PREFIX_QA` (BE falls back to the old var); rows that are still just a prefix don't count toward Create
- Creation via Jira bulk API with the project's real sub-task type; success screen links every created key
- Deep-linkable: `/subtask-gen/DX-123`
- New env params: `CONFLUENCE_SPEC_SPACE` (empty = all spaces) and `SUBTASK_PREFIX` (default name prefix)

## 🖼 Inline media in story details

- Pictures and videos embedded in a card's **description and comments now render in the app** instead of the "open in Jira" placeholder:
  - images → inline (lazy-loaded); **click opens a full-size lightbox in the app** (Esc/click closes) — direct navigation would download the file, so the viewer never leaves the page
  - videos → playable `<video>` player with preview frame (`preload="metadata"` — no download until you press play)
  - other files / unmatched media → a 📎 filename link
- Media streams through the existing `/jira` proxy (auth injected server-side, token never in the browser); matched to attachments by filename from the ADF `alt`
- Zero impact on list pages — bytes are only fetched on the detail page you opened

## 🧹 Final review & hardening (closing 0.1.7)

Independent code review of the beta.2 diff found and fixed 8 issues before release:

- **Integration Plan**: Sync disabled until the plan finishes loading (clicking early would have re-added every story with empty fields, wiping saved inputs); sync results are discarded if you switch release mid-sync (prevented cross-release data corruption); switching release with unsaved edits now asks for confirmation; sync commits in ≤450-op chunks (Firestore's 500-op batch cap)
- **Spec Wizard**: partial bulk-create failures now remove only the rows that actually got created (retry can no longer duplicate subtasks); the project's sub-task type is re-resolved when switching stories (no stale cross-project type); a clear warning appears if a picked assignee's Jira account couldn't be resolved (rows were silently created unassigned); custom-row ids made collision-proof
- Removed one unused import; re-verified zero mock/debug leftovers, valid JSX throughout, and all cross-file references
- Full test coverage for the 0.1.7 features (**125 unit tests / 24 files**):
  - `integrationApi` — sync add/refresh-meta/keep-inputs/delete, ≤450-op batch chunking, save field whitelist
  - `IntegrationPage` — local-only editing + Save bar, only-changed-rows saved, Sync locked while dirty, sync passes stored rows, delete confirm, empty state, role date headers
  - `SubtaskGenPage` — role tab counts, spec+QA dedupe into "Already covered", foreign-space skip, per-active-role create, partial-failure retry keeps only failed rows, accumulating created card
  - `claimedSpecUrls` / `stripBrackets` (wizard dedupe primitives)
- **Version display flag**: full versions show clean (`v0.1.7`); only pre-release versions (`x.y.z-beta.N`) append the git build hash — driven by package.json, single source of truth
