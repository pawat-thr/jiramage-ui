# v0.1.7 (beta) — What’s new since v0.1.6

## 🔀 PR Review

- **Two sections on the board:**
  - **"Waiting for your review"** on top — PRs where YOU are a reviewer and the status is not yet Approved or Merged, with a count badge. Independent of the filters, so nothing you owe the team can hide.
  - **"All PRs"** below — the full filtered list, unchanged.
  - The top section disappears entirely when you're caught up.

## 📄 Subtask → Confluence spec links (My Tasks & Team Task)

- Subtask rows now show a **"📄 spec" chip** linking straight to the matching Confluence spec page — e.g. subtask `[BE][MP] mp-merchant/pre-order/orders/get-order-detail` links to the page `[R6.1#5][S12] POST /campaigns/v1/mp-merchant/pre-order/orders/get-order-detail`
- Candidate pages come from the parent story's **remote links** ("mentioned on" Confluence pages) plus smart links in its **description** — no Confluence API needed
- Matching is token-sequence based with a confidence threshold: endpoint-style names match precisely (get-order-**detail** vs get-order-**list** are kept apart); short generic names ("[QA] Test case") deliberately never match
- Links are fetched lazily per parent story and cached for the session; both old (`viewpage.action?pageId=`) and new (`/pages/<id>/slug`) Confluence URL forms supported
- 9 new unit tests including the real-world example (54 total)

## 📄 Meta

- Version **0.1.7-beta.1** everywhere (package.json, `APP_VERSION`, proxy User-Agent) — beta number bumps (beta.2, beta.3…) as features land; the plain **0.1.7** tag is reserved for the finished version

## 💬 @Mentions in PR comments

- Type **@** in the comment box → autocomplete dropdown of team members (filter as you type; arrows/Enter/Tab to pick, Esc to dismiss)
- Mentions render **highlighted** in posted comments
- Every mentioned member gets a **"mentioned you in a comment on"** inbox notification; the PR owner still gets the plain "commented" one — but never both (mention wins), and never for your own mentions of yourself
- No Firestore rules change needed (same `notifications` collection)
